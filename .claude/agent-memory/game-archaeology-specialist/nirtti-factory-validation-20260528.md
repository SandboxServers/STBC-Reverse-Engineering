# nirtti-factory-catalog.md V5 Validation (2026-05-28)

## Outcome
Foundation claims hold. Doc structurally correct. Surface-level corrections needed but
the per-row factory + registration + class-string addresses are reliable.

## Key MCP techniques

### Counting registrations precisely
- `get_xrefs_to(0x009a2b98)` returns 237 entries.
- 234 are (READ, WRITE) pairs from 117 registration functions.
- 2 are consumer READs: FUN_008176b0 (NiStream::LoadObject), FUN_00818150 (LoadObjectAlt).
- 1 is a standalone READ at 0x00816c40 — NOT inside any Ghidra function, an orphan
  shutdown-destructor snippet that calls vtable[+0] on the hash table.
- Final count: 117 registrations exactly. (NOT 118 — the snapshot's (237-1)/2 calculation
  forgot to subtract the 2 consumer READs separately.)

### Pattern verification — registration template
Decompile any one of these and you have all 117 (they are bit-for-bit identical structurally):
- TGDimmerController FUN_00455060 (cluster 0x004xxxxx)
- NiListener FUN_0078cbd0 (cluster 0x0078xxxx)
- NiNode FUN_007e3670 (cluster 0x007Exxxx — most-cited exemplar)
- NiBezierCylinder FUN_0084ca60 (cluster 0x0084xxxx)

### Factory pattern — two flavors
Decompile any factory and look at the first bytes:
- `6A FF 68 xx xx 88 00 64 A1 00 00 00 00 50 ...` = SEH prologue → real concrete factory
  with NiAlloc(N) + vtable write. Example: 0x00455320 TGDimmerController.
- `C3 90 90 90 90 90 90 90 90 90 90 90 90 90 90 90` = RET + NOP padding → abstract-base
  stub factory. Example: 0x007d8810 NiObject.

The 17 `DAT_*` factories in the catalog are all abstract bases. The other 100 are concrete
classes that allocate fixed-size instances.

### TG-class identification
Doc claims 2 TG NiRTTI registrations. Bare-string search in `.data` at 0x008daed4 region
finds THREE consecutive TG strings:
- 0x008daed4 TGDimmerController (5 DATA xrefs incl. FUN_00455060 registration)
- 0x008daee8 TGFuzzyTriShape (5 DATA xrefs incl. FUN_00456740 registration)
- 0x008daef8 TGOverlayController (1 DATA xref only, from FUN_00457550 — NOT a registration)

So exactly 2 TG NiRTTI classes confirmed. TGOverlayController uses a different runtime-type
mechanism.

## Guard flag column is systematically wrong
Sampled 10 entries; 8 had wrong guard-flag addresses, 2 happened to be right (NiNode @
0x009a18a0, NiBezierCylinder @ 0x009b32f0). The doc's column appears generated by some
flawed sequential-offset extrapolation. To validate per-row guard flags requires per-row
decompile — recommend dropping the column entirely.

## NiAlloc address — discrepancy with engine-snapshot
The engine-snapshot says NiAlloc at 0x00717840. The nirtti factory registrations and
this validation pass both confirm NiAlloc at 0x00718cb0. The snapshot has the wrong
address — should be updated.

## Open question — 14 unregistered NI classes
RTTI catalog claims 129 NI classes; only 115 NI have NiRTTI factory registrations.
14-class gap. Doc's "Notable Absences" lists 4 (NiDDImage, NiDDBufferImage,
NiCloneExtraData, NiProvider_Info). Other 10 unenumerated. Resolving requires either
list_strings after Ghidra defines .rdata strings, or enumerating NI vtable cluster from
the partner's RTTI catalog.

## Open question — hash-table vtable slots
8 function pointers exist at PTR_FUN_0088b7c4. Doc only documents 4 (hash, compare,
setEntry, deleteEntry). Slot [+0] is the destructor (verified via 0x00816c40 standalone
READ). Slots [+0x14], [+0x18], [+0x1C] are unidentified. Low priority.

## Address-range claim — minor refinement
Doc's "Factory functions: 0x00455320 - 0x00850a30" range is CORRECT (the NiBezierCylinder
*factory* is at 0x00850a30 — higher than its *registration* at 0x0084ca60). Doc's separate
"Registration functions: 0x00455060 - 0x0084ca60" is also correct. The summary table is
consistent if you read carefully.
